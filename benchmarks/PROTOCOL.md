# Evidence protocol

Principles:
- Mechanisms are claimed on day one; **numbers only after measurement**.
- Full transcripts published for every run; n disclosed; illustrations labeled.
- No leaderboard or "higher score, lower bill" claims from small n.

## Variants

Two variants share this protocol:

- **Cheap suite (implemented, `run_bench.py`)** — 3 tasks, small fixtures,
  `deepseek-flash` (non-thinking), n=1 per arm, cumulative cost guard $3.
  Designed to cost well under €5 total. The compaction-survival task is
  deferred in this variant (forcing compaction requires large context).
- **Full suite (specified below, not yet run)** — larger fixtures, frontier
  model, n≥3, includes compaction-survival.

### Cheap suite parameters (as implemented)

- Fixture repo: 60 Python files across 3 subpackages; 24 files contain
  `calc_total` (120 occurrences); exactly 7 functions span >30 lines
  (ast `end_lineno - lineno + 1`); sentinel comments guard untouched content.
- `server.log`: exactly 20,000 lines; ground truth covers error count, top
  error code, checkout mean latency, distinct timeout users, first FATAL ts.
- Arms: `kernel` (plugin enabled) vs `baseline` (plugin absent). Identical
  arm-neutral prompts, identical bench agent (minimal system prompt, step
  cap), same model `deepseek/deepseek-flash`, hermetic `opencode run
  --standalone` per run, `--auto` for unattended permission approval.
- Integrity: `ground_truth.json` is moved out of the agent workspace during
  the run and restored only for the verifier.
- Metrics source: per-step `cost`/`tokens` events from `--format json`
  (OpenCode's models.dev-based estimate; DeepSeek peak/off-peak billing may
  differ slightly — projections use peak rates as the upper bound).
- Runner aborts remaining runs if cumulative cost reaches the guard.

## Setup (full suite)

- Hermetic fixture repo generated by script (no network, no live services):
  ~200 Python files containing a known symbol, a synthetic ~100k-line log with
  known ground truth, and a codebase with known function-length statistics.
- A/B arms: plugin enabled vs disabled. Same model, same variant, same prompts,
  same fixture state (regenerated per run).
- Runner: `opencode run` non-interactively. One owner per live run; model spend
  serialized.

## Tasks

1. **bulk-rename** — rename a symbol across ~200 files and verify.
   Verifier: exact occurrence counts before/after (grep ground truth).
2. **log-analysis** — answer 10 questions over the ~100k-line log.
   Verifier: exact expected answers.
3. **repo-audit** — AST-parse the fixture repo; report every function longer
   than 50 lines. Verifier: ground-truth list.
4. **compaction-survival** — long multi-stage task with heavy intermediate state,
   forced through at least one compaction. Verifier: final artifact correctness
   plus compaction count and post-compaction re-read volume.

## Metrics (per run)

Turns · input/output tokens · cost · wall time · compaction count · task success.

## Publication

`benchmarks/runs/<task>/<arm>/` — transcript + metrics JSON, plus a summary table
in `benchmarks/RESULTS.md`. Start at n=1 per arm (disclosed); extend to n=3 where
variance matters. Worked examples in the README are labeled as illustrations,
never as measurements.
